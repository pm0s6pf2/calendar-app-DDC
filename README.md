# 日めくり Google連携テスト版

HTML / CSS / JavaScriptを分離した開発用バージョンです。
既存アプリへの統合済み完成版ではありません。元ファイルは変更していません。

## 今回追加したもの

- カレンダーの日付に結び付ける日記欄。日記用の日付入力はありません。
- 日記とお気に入りを同じスプレッドシートのDiary / Favoritesに保存。
- ファイルIDで関連付けるため、画像名が変わっても関連付けを維持。
- Google Pickerで対象画像を選んで許可→変更前後を確認→Driveの名前を変更。
- 重複日付・変更権限・別操作による名前変更を直前に確認。
- 日付が入れ替わった2枚の画像を、確認後に交換。拡張子と画像IDは保持。
- 途中で中断した入れ替えを、同じブラウザ・アカウントで復旧。
- 日記を、スプレッドシート上の保存履歴も含めて削除。
- 未保存の日記を移動で破棄する前に確認。
- 画像取得の古い応答を無効化。スライドは取得処理を待って進む。

デモで日記・お気に入り・名前変更を試せます。デモデータはページを閉じると消えます。
Google接続後、変更・新規作成・保存の操作は実際のGoogleデータを書き換えます。
実アカウントでのOAuth・Picker・Drive・Sheets結合テストは未実施です。

## GitHub Pagesで公開する手順（最初に実施）

まだGoogle設定をしていない場合は、以下の順で進めてください。
このZIPを作っただけではGitHubへのアップロードや公開は行われていません。

### 1. ファイルを配置する

1. ZIPを展開し、calendarフォルダ内のファイルを取り出します。
2. GitHubで新規リポジトリを作るか、既存リポジトリを開きます。
   既存アプリを動かしている場合は、まず別のテスト用リポジトリで確認してください。
3. リポジトリの最上位にindex.html、style.css、script.js、README.mdを配置します。
   GitHub画面なら「Add file」→「Upload files」でアップロードできます。
   calendarフォルダごと入れる場合は公開URLに/calendar/が追加されるため、この手順では中身を配置します。
4. 変更をコミットします。COMMIT_MESSAGE.txtの内容をコメントに使えます。
   ZIPファイルだけをアップロードしてもアプリは動きません。

### 2. Pagesを有効化する

1. リポジトリの「Settings」→「Pages」を開きます。
2. 「Build and deployment」の「Source」を「Deploy from a branch」にします。
3. Branchをmain、Folderを「/(root)」にしてSaveします。
   別ブランチで管理している場合は、ファイルを配置したブランチを指定します。
4. ActionsでPagesの公開処理が完了したことを確認します。
5. Settings → Pagesに表示されたURLを開きます。
   通常のプロジェクトサイト例: https://YOUR_ACCOUNT.github.io/YOUR_REPOSITORY/
6. この段階ではGoogle未設定なので、サンプル表示ができれば問題ありません。

### 3. Google設定に使うURLを確認する

例えば公開URLが https://example.github.io/calendar/ の場合：

| 用途 | 設定値の例 |
|---|---|
| アプリを開くURL | https://example.github.io/calendar/ |
| OAuthの承認済みJavaScript生成元 | https://example.github.io |
| APIキーのウェブサイト制限 | https://example.github.io/* |
| Pickerのiframe用ウェブサイト制限 | https://docs.google.com/* |

OAuthの生成元にはリポジトリ名やパスを含めません。
独自ドメインを使う場合は、実際に開く独自ドメインの生成元を登録してください。
このコードはGISのトークン方式なので、コードフロー用のリダイレクト先を新規実装する必要はありません。

### 4. Google設定後に更新する

1. 下記「Google側の準備」を実施します。
2. script.jsのCONFIGを設定してコミットし、GitHubへ反映します。
3. Pagesの公開完了後にページを再読み込みします。
4. Google接続・フォルダ選択・保存先作成を順に確認します。
5. 最初の改名・入れ替え・削除テストには、コピーした画像とテスト用保存先を使ってください。

GitHub Pagesは静的ホスティングです。ページのコードは閲覧者から見えます。
日記・画像本体・トークン・client secret・認証情報JSONをリポジトリに入れないでください。
今回のコードは日記をGoogleスプレッドシートに保存します。日記の本文をソースに書きません。
OAuthクライアントID・プロジェクト番号・制限付きブラウザAPIキーはクライアント用の設定値です。
APIキーを記載してもGoogle Driveの非公開画像が公開されるわけではありません。

## Google側の準備

1. OAuthクライアントIDと同じGoogle CloudプロジェクトでDrive API、Sheets API、Google Picker APIを有効化。
2. Webアプリ用OAuthクライアントの承認済みJavaScript生成元に実際のURLを追加。
   GitHub Pages例: https://YOUR_ACCOUNT.github.io （パスなし）
   ローカルでも使う場合は追加で http://localhost:8000
3. OAuth同意画面を設定。テスト公開の場合は利用アカウントをテストユーザーに登録。
4. script.js先頭のCONFIGを設定。
   - clientId: OAuthクライアントID。添付元コードの値が入っています。
   - projectNumber: 同じCloudプロジェクトの「プロジェクト番号」。ID文字列ではありません。
   - pickerApiKey: ブラウザ向けAPIキー。
5. ブラウザAPIキーにはウェブサイト（HTTPリファラー）制限とAPI制限を設定。
   Pickerの公式ドキュメントに従い、`https://YOUR_ACCOUNT.github.io/*` と `https://docs.google.com/*` を設定。
   API制限はGoogle Picker APIとGoogle Drive APIを選択。このコードのSheets通信はOAuthトークンを使用します。
   https://developers.google.com/workspace/drive/picker/guides/web-picker
   クライアントシークレットやアクセストークンはソースに書かないでください。
6. GitHub Pagesの公開URLでアプリを開きます。
   任意でローカル確認する場合は、このフォルダで `python -m http.server 8000` を実行し、http://localhost:8000 を開きます。
   ファイルを直接開く方法ではデモのみ利用してください。

## 使い方

1. 「Googleに接続」からdrive.readonlyとdrive.fileを許可。
   既存のフォルダ閲覧用に読み取り権限を継続し、選んだファイル等への編集権限を追加します。
2. 「画像フォルダ」でフォルダを選ぶ。日付形式のpng/jpg/jpegを一覧化。
3. 初回は「保存先を新規作成」。日記とお気に入り用の新規スプレッドシートが作られます。
4. 別端末では「既存の保存先を選ぶ」で同じスプレッドシートを指定。
5. 画像の下の日記欄から保存、お気に入りボタンから登録・解除。
6. 他の端末の変更を取得するには「再読み込み」。リアルタイム同期は未実装。
7. 名前変更は「日付を修正」→Pickerで表示中の画像を選択→日付を指定→適用。
   対象画像の選択を取り消せば名前変更は始まりません。
8. 「切断」はアプリ内のトークンを破棄します。Google連携許可そのものは取り消しません。

## 保存形式

Diary: entry_id / file_id / calendar_date / text / updated_at
Favorites: event_id / file_id / favorite / registered_at / updated_at

日付はcalendar_dateのみ。updated_atは保存処理の時刻です。
日記は1画像につき最新の1件を表示します。編集時には履歴を追記します。
同じ月日でも別ファイルなら別の日記になります。
画像を改名した場合、既存履歴のcalendar_dateは保存時の値として残ります。
次の保存から新しい日付が記録されます。画面には保存時の日付を明示します。
存在しない日付・画像未登録の日の日記保存は、この版ではできません。

お気に入り解除もFALSEの履歴を追記し、最新の行で登録状態を判断します。
同時編集は最後に追記された内容が表示されます。編集競合の対話解決は未実装です。
履歴行を手動で並べ替えると最新判定が変わるので、元の2シートは並べ替えないでください。
別シートに表示用の集計を作ることは可能です。
本文はRAW指定で書き込み、先頭の「=」などを数式として解釈させません。
通信切断時、保存が成功したか不明な場合があります。無条件の自動再送は行いません。

## 残っている検証・作業

- 実アカウントで権限取得、保存、別端末での再読み込み、改名、取り消しを検証。
- Google API設定・ブラウザ画面の実動作確認。
- 元アプリの永続キャッシュ管理・容量設定との統合。今回の版は画像を都度取得します。
- NotFoundは文字プレースホルダー。指定画像への差し替えは別途。
- Driveの一覧右側は日付サムネイル。実画像サムネイルの連携は未実装。
- 改名と重複確認は複数リクエストのため、他端末の同時操作まで完全には排他できません。
- 改名履歴の取り消しは現在のページを開いている間のみ。
- 保存先作成直後のヘッダー書込が失敗した場合、作成済みファイルは残ります。
  「保存先を開く」で内容を確認し、正しいヘッダーを整えてから再選択してください。

## 日付が入れ替わった2枚を修正する

1. 画像Aを表示して「日付を修正」を押し、Pickerで画像Aを選びます。
2. 画像Aの正しい日付を入力します。
3. その日付の画像Bが1枚見つかると、A・Bそれぞれの変更前後の名前が表示されます。
4. 「この画像と日付を入れ替える」にチェックします。
5. 適用ボタンを押し、Pickerで画像Bを許可します。最後の確認で2枚の日付を交換します。
6. 取り消す場合は、このページを開いている間に「元に戻す」を使います。

例: Aの2026-10-25.png → 2026-10-24.png、Bの2026-10-24.jpg → 2026-10-25.jpg。
画像形式を変えないため、拡張子はそれぞれのファイルに残し、日付部分を交換します。
候補が複数ある場合は自動で選ばず停止します。
入れ替えはAを一時名に変更→Bを変更→Aを確定、の順で実行します。
Google Driveはこの3操作を一括の原子的処理にできないため、途中で通信切断が起こり得ます。
開始前に同じブラウザに復旧情報（ファイルIDと名前）を保存します。保存不可なら変更しません。
中断時は「中断した入れ替えを復旧」から開始前の名前へ戻します。
ページを閉じた場合も同じブラウザで同じGoogleアカウントに再接続してください。
復旧完了までは新しい改名・フォルダ変更を止めます。復旧情報を削除しないでください。
別操作による予期しない改名・移動が見つかった場合は復旧を停止します。
その場合はDrive上の2枚を確認し、記録した元の名前と照合してください。
他端末から同じファイルを同時に改名しないでください。完全な同時実行制御は未実装です。

## 名前変更後の日記・お気に入り

ファイルIDは、既存ファイルの名前だけを変更する場合には変わりません。
日記とお気に入りは元の画像そのものに付いたままです。2枚を入れ替えても同様です。
ただし画像を削除し、新しいファイルとしてアップロードし直すと別のIDになる場合があります。
Diaryシートのcalendar_dateは「その日記を保存した時点の日付」で、既存履歴は書き換えません。
改名後に日記を保存すると、新しい日付の履歴が追加されます。
日記を『日付の枠』に残したい設計とは異なります。この版は『画像』に紐付けます。

## 日記を削除する

1. 対象画像を表示し、「日記を削除」を押します。
2. 確認画面で、履歴も含めて削除することを確認します。
3. Google接続中は、その画像IDに一致するDiaryシートの行をすべて削除します。
4. 画像本体、Favoritesシート、他の画像の日記は削除しません。

古い日記が再表示されるのを防ぐため、最新の1行だけでなく、その画像の全履歴を削除します。
アプリ上の取り消しはありません。Google側の変更履歴・バックアップまで消す操作ではありません。
削除の直前に行の内容を再確認し、下の行から1つのbatchUpdateで削除します。
行の読取りと削除は単一トランザクションではありません。
削除中は他端末・Sheets画面で同じシートの行削除や並べ替えをしないでください。
保存履歴の手動並べ替えは、通常の最新行の判定にも影響します。
削除結果が不明な場合は自動再試行せず、再読み込みして保存先を確認してください。

## スマートフォンへの表示（今後の候補・未実装）

- ホーム画面に起動アイコンを置く: ブラウザの「ホーム画面に追加」で利用可能。
